Make a game with AI

For fixed-package acceptance follow the development guide and use SDK bgparty-game accept. It does not rebuild or follow mutable build outputs. Each run owns its address, storage identity, connected-browser tab and evidence. Restore legal logs through normal page controls and actually exercise the affected behavior. Coordinate only shared browser controls with short leases; do not serialize entire development tasks. Follow the project's listener authorization policy.

Give the complete project folder to a coding assistant that can read/edit local files. Ask it to read AGENTS.md and docs/ first. A chat-only AI can help design or write code, but you must perform installation, builds and browser actions. The main BGParty repository is unnecessary.

Work in stages

Agree on rules and the state/action/view model, including information privacy. Choose an example, rename together, and implement playable pure rules.

Run check and build, align metadata and exported capabilities, then preview after obtaining any required port permission. Actually complete a match. For failures, provide terminal output, reproduction steps and expected behavior.

Improve layouts, assets, rules and both languages. Check mobile/desktop. Prefer SVG and public SDK components. Check contracts before advanced features; do not allow direct game networking or access to host secrets.

Follow Publishing and verify actual installation, networking, offline use and updates in BGParty. Ask the assistant to distinguish verified cases from untested ones. Generated code or successful compilation is not full game acceptance.
